# TaoChronos V2 — verifiable knowledge discovery and ancient–modern translation

V2 turns the capabilities of the study layer and the research engine into an agent that answers a question the way a
careful scholar-clinician would: from the witnesses, through the philology, across to modern medicine only as far as the
evidence allows, with every statement it makes audited before it is shown.

Two principles run through all of it.

1. **Rules screen, a model judges.**  Every capability runs on rules first — deterministic, fast, repeatable, the numbers
   in the documentation are theirs.  A model, when one is configured (`--llm provider:model`: MiniMax, DeepSeek, Qwen,
   Kimi, GLM, Doubao, Poe, LiteLLM, Claude …; see [models.md](models.md)), reviews only what the rules leave uncertain,
   may add what they missed as validated spans, and writes cited summaries.  Its output is untrusted: it is checked
   against a schema, against the text (exact spans), against the presentism guard, and in several places it **may lower
   a result but never raise it** (a bridge level, an audit verdict).
2. **Every link says who asserts it.**  The source says it, a scholar or curator interprets it, a model extracted or
   inferred it, modern evidence supports it, or it is a hypothesis — and a reader can walk from any conclusion back to the
   words of a witness.

| Component | Where | What it does |

| Evidence Audit (S15) | `verification/audit.py`, `plugins/classics/audit.py` | a claim decomposed into atomic claims, each checked by its kind; five verdicts |

A manifest records the skill's version, typed inputs and outputs, dependencies, `requires_llm` (none / optional /
required), its deterministic and model steps, its tool calls (with `for_each` over the context: passages, terms, drugs,
diseases, statements), validators and the evaluation suites that measure it.  `taochronos skills` prints them and checks
the registry: every skill owned by an agent that lists it, depending on known skills, calling known tools its owner has
permission for; no dependency cycles; core agents never hold commit permissions; delegates are specialist roles of the
research engine (curator, philologist, extractor, semanticist, lineage, scholar, evolution → Classical Scholar;
ontologist, modern_evidence, hypothesis → Translational; evidence, skeptic, statistician → Critic; director,
meta_reviewer → Orchestrator).

## From a question to an audited answer

```bash
taochronos ask "消渴的概念如何随时代演变？与现代糖尿病有何异同？" --plan-only   # the compiled workflow
taochronos ask "消渴的概念如何随时代演变？与现代糖尿病有何异同？"               # run it
taochronos ask "…" --llm minimax:MiniMax-M2.7 --online                           # a model's review; PubMed in S13
```

1. **Compile.**  The question's words select skills (演变 → S09; 现代 or a named disease → S10–S12; 研究证据 with a named
   drug → S13; 真实世界, 队列, 患者中 → S14; 版本, 异文 → S04–S05; 训诂 → S03 …); dependencies are closed over; S01 opens
   every plan and S15 closes it.  A model may propose a plan — only known skills, never without S01 and S15 — and it is
   validated before use; otherwise the rules' plan stands.
2. **Run.**  Each skill's calls go through the kernel's tool scheduler **as the owning core agent** (the policy checks each
   permission).  Each call is an artifact in `<data>/workspaces/<run>/steps/`, keyed by the skill's version, the tool and
   the arguments: the same question resumes where it stopped, and a step already done is read, not redone.
3. **Answer.**  The Orchestrator composes the statements from the artifacts — what the witnesses say (verbatim quotes),
   how the bridge reads the descriptions, what modern literature exists by level — and S15 audits every one of them.
   The report (`report.md`) shows each statement with its verdict.

On the full corpus the example question runs in about 15 seconds after the store is loaded; its statements are verbatim
quotes (SUPPORTED) and bounded comparisons.

## Evidence Audit (S15)

| Claim kind | Example | Checked by |
|---|---|---|
| historical | 《金匮要略》载「男子消渴，小便反多」 | the work known; every quote found verbatim (variant forms and marks aside) in the cited work |
| interpretive | 「几几」者，伸颈之貌也，成无己注 | a gloss or commentator cited; the gloss found in that commentator's works |
| mapping | 「…」所述症状在表型上与糖尿病相容 | presentism guard (no equation, no retrospective diagnosis, no 即/就是/相当于); the bridge's level on the quoted passage; its conflicts |
| modern | 黄连素可降低2型糖尿病患者的血糖 | modern records whose design and population can carry the claim's level |
| inference | …，所以黄连可以治疗2型糖尿病 | an inference leap from the historical record to modern efficacy — unless put as a hypothesis to test |
| clinical | 每日服30克 | refused: no clinical or dosage advice; toxic materials flagged |

Verdicts: `SUPPORTED` (every atomic claim passes), `PARTIALLY_SUPPORTED`, `CONTESTED` (the evidence speaks against a
part), `INSUFFICIENT_EVIDENCE`, `UNSUPPORTED` (a check fails).  Quotations are never split; caveat-only sentences
(这是表型相似，不是回溯诊断) assert nothing and are skipped.  A model critic may add concerns and lower a verdict.
**SUPPORTED means the checks this system can run pass — not that the claim is true.**

```bash
taochronos audit "《金匮要略》载「男子消渴，小便反多」，所以肾气丸可以治疗糖尿病。"
taochronos graph --passage jinkui.13.xiaoke1 --graphml xiaoke.graphml
taochronos graph --passage jinkui.13.xiaoke1 --node "resemblance:jinkui.13.xiaoke1->diabetes_mellitus"   # its lineage
```

## Modern evidence (S13)

`taochronos modern search 黄连 --disease diabetes_mellitus --online` builds a PubMed query from the crosswalk
(`domains/modern/crosswalk.yaml`: 黄连 → Coptis, berberine; formulas by their romanised names) and the disease's English
name, fetches records and abstracts, and types each by its publication types, MeSH headings, title and abstract: an RCT
in rats is **animal** evidence; network pharmacology and docking are **in silico**.  The summary counts records by type and
population and says how many can carry a claim of efficacy in people.  The **cross-level guard** (`protocol/modern.py`)
refuses animal or cell work read as efficacy in people and a computational prediction read as an effect.  PubMed is
queried only when asked (`--online`, `TAOCHRONOS_PUBMED=1`); requests carry the tool name (and `NCBI_API_KEY` /
`NCBI_EMAIL` if you set them), are spaced and retried, and every answer is cached.  The **safety table**
(`domains/modern/safety.yaml`: aconite, aristolochic acid, mercury, arsenic, lead, strychnine, Tripterygium …) only warns.

## Real-world data (S14)

```bash
taochronos rwd synth omop.sqlite                                  # a synthetic OMOP database (fake people)
taochronos rwd ask "2型糖尿病患者中，使用黄连素与糖尿病肾病的关系" --db omop.sqlite
taochronos rwd spec "…" --llm deepseek:deepseek-chat              # a model proposes the spec — never SQL
```

The question becomes a `StudySpec` (exposure and outcome concept sets resolved in the database's own `concept` table,
population, design, washout and follow-up); the spec is validated (schema and vocabulary); it is compiled into one fixed
new-user cohort query; the SQL is checked (read-only, OMOP tables only, every value a bound parameter) and run on a
read-only connection.  The result is counts, risks and a crude risk ratio with its interval — and the caveats:
observational, unadjusted, and on synthetic people a check of the compiler, not a finding.

## Limits

* Levels and verdicts are not calibrated probabilities; the disease profiles and the homonym notes need clinical and
  historical review.
* The audit checks what can be checked mechanically (quotes, glosses, levels, evidence types, leaps); it does not judge
  a historian's argument.
* PubMed typing reads indexing, not full texts; a record's type is a reading to be checked.
* The RWD path is a compiler with guard rails, not a study: a real one needs a protocol, adjustment and review.
