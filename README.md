# TaoChronos · 道乃久

**面向中医古籍的可溯源知识发现与治学系统** · 智能体**道乃久**（模型 **Tao-R1**），**医哲未来人工智能研究院（IMPF-AI）发布**
*A provenance-grounded research harness for the Chinese medical classics — for scholars, students and discovery.*

**[在线使用 · 网页对话](https://chat.impf.ai/)** · [English README](README.en.md) · [网页端](docs/web.md) · [V2](docs/v2.md) · [古今桥接](docs/bridge.md) · [模型接入](docs/models.md) · [治学](docs/study.md) · [任务规格](docs/tasks.md) ·
[架构](docs/architecture.md) · [智能体](docs/agents.md) · [发现引擎](docs/discovery.md) · [评测](docs/evals.md) · [数据格式](docs/data.md) · [路线图](docs/roadmap.md) · [ADR](docs/adr/)

TaoChronos 把 966 部中医古籍（约 1.23 亿字、205 万段）整理成一个**可检索、可断代、可溯源**的语料库，并在其上提供两层能力：

- **治学**：按考据传统回答学者与学生天天要问的问题——这段经文还见于哪些书、各本异文如何（经文互见·集注）；
  一首方的原方是什么、后世如何加减（方源考）；一味药的性味归经何时出现（药性源流）；一个术语何时盛衰、所指为何（术语源流）；
  这个本子是哪个朝代的刻本（避讳断代）；各时代引谁的书、宗谁的说（引书与引人）；以及学习卡片、阅读门径与研究数据集。
- **深层发现 2.0**：读出文献自身的结构——**版本谱系**（多本对校、谱系树、共同异文与污染）、**语义复用与思想传播**（直接引用、
  节略、撮要、转述、解释性改写、引而驳之……及一部书的历代接受）、**文本地层**（文风分层、断代证据、作者归属）、**医案轨迹**、
  **医理论证图**、**语义演变**（义项变点与候选新义）、**佚书辑佚**。七项都是确定性能力，接入工具网格，由现有智能体调用，
  不新增智能体；候选生成不等于证明，每个标签都附上触发的规则与读到的数值。
- **任务规格 v1.0**（[docs/tasks.md](docs/tasks.md)）：把“中医古籍计算语文学与知识发现”路线图的 27 项任务（L0 数字化 → L1 句读
  与篇章 → L2 语义知识 → L3 数字考据 → L4 知识发现 → L5 研究智能体）逐项落到输入、输出 JSON Schema、工具与智能体、算法、评测、
  金标准与人工复核，并补齐所缺：**句读**（原字不改）、**条文结构**、**训诂**、**集注与注家比较**、**争议**、**异文分级**、**配伍**、
  **方证网络**、**学派**、**名称**、**传播链**。
- **V2：可验证的知识发现与古今转译**（[docs/v2.md](docs/v2.md)）：**规则先筛、模型复核**——每项能力先由规则完成，模型（LiteLLM、
  MiniMax 国内站、Poe、DeepSeek、通义、Kimi、智谱、豆包、Claude……）只裁决规则拿不准的项、补读规则漏掉的片段（须为原文精确片段）、
  写带引证的综述，并且在若干处**只能调低、不能调高**。在此之上：版面理解与识读（T1–T2）、中医实体识别（T7，24 类）、五层今译（T10）、
  地域（T27）；**古今桥接引擎**（古代表型 → HPO 类型化投射 → 64 种现代疾病谱，定性强度而非概率，**表型相似而非回溯诊断**，
  亦可由今病溯古）；**六层证据图谱**（每条边标明由谁断言）；**证据审计**（逐条拆解、按类核查、五级结论）；**现代证据**（PubMed 按
  研究设计与对象分级，动物与网络药理不可充当人体疗效）与**真实世界数据**（问题 → 研究规格 → 校验过的 OMOP 查询，模型从不写 SQL）；
  **15 项技能清单、4 个核心智能体、工作流编译与可续跑执行**（`taochronos ask "问题"`）。
- **研究**：由研究主管智能体 **TaoChronos** 调度 16 个专科智能体，把一个研究问题变成**可重放、可审计、可证伪**的过程：
  研究契约 → 证据基础 → 模式挖掘 → 假说 → 证伪 → 门控 G0–G8 → 专家核验。研究契约是**可执行的**：任务跑完只是“执行完毕”，
  研究是否被接受由验证者按合同逐条评判（`research_accepted` / `needs_expert` / `inconclusive` / `budget_exhausted`）；
  引文为真不等于解读为真（每条主张须由其引文**陈述**出来），模型的提议不等于验证的结论，内部分数不等于外部证据
  （[ADR 0009](docs/adr/0009-boundaries-contract-and-evaluation-layers.md)）；“失传”“隐性”这类**缺席论证**以整个研究范围内的明确陈述检验，
  研究价值在全量语料上按年代**盲测**并与基线比较（[ADR 0010](docs/adr/0010-speed-cruxes-and-research-value.md)）。

两层共享同一原则：**每一个结论都落到逐字可核的原文见证上**（书、卷篇节、年代、层次、录文来源与授权），规则抽取标明为机器阅读，
由人去核对与定夺。

## 一、它能做什么

| 面向 | 能力 | 入口 |
|---|---|---|
| **文献学研究者** | 经文互见与集注式校勘记（同书异本 / 引文 / 互见；异文、脱、衍、倒）；避讳断代；引书与引人网络、接受史 | `study concordance` · `study taboo` · `study citations` |
| **句读与训诂** | 白文自动断句标点（从编者标点本学得，只插入标点、原字全保）；条文结构（前提、病、症、脉、证、治则、禁忌、方、组成、煎服、加减、预后）；诸家训诂（…者…也、貌、音、反切、读为、当作、一作、通），首释者与年代 | `study punctuate` · `study clause` · `study glosses` |
| **注家与学派** | 集注对齐与注家比较（照录、承袭、同解、增益、异解、驳、从）；争议（谁驳谁、驳什么，转述者另记）；学派（本派比同时代他书多用的词、药、方与互引）；名称（异名、通行之名的更替、词表未收之名） | `study commentaries` · `study disputes` · `study schools` · `study names` |
| **方剂学、本草学、医史研究者** | 方源考（原方、通行方、加减化裁、同名异方、同方异名、配伍比例、历代计量折算、历代主治、方歌）；药性源流（性味、毒性、归经、升降浮沉的首见与演变）；术语源流（分期频率与区间、趋势检验、首见、搭配、义项）；配伍规律（NPMI、Fisher 检验与 BH 校正、药群）与方—证—症—药网络 | `study formula` · `study herb` · `study term` · `study pairs` · `study network` |
| **需要数据的研究者** | 带出处、年代与授权的开放数据表（Frictionless 数据包），可直接做统计与可视化 | `study dataset` |
| **学生与自学者** | 方证填空卡、组成卡（附方歌）、药性卡、经文卡，导出 Anki；按“源头经典 → 历代发挥 → 专书 → 医案 → 近代”的阅读门径 | `study cards` · `study reading` |
| **校勘与版本学** | 多本对校的异文单元（异文、脱、衍、倒、缺文、结构性增删、异体）与异文分级（剂量、否定、方药先审）、邻接法谱系树、共同异文分组与污染检测、单本概况、TEI 校勘记；一条条文的传播链（共同创新）；版本与影像见证（库中各录本的底本、年代、藏所与页面影像，各馆数字化刻本与抄本的索书号、IIIF 清单与授权） | `study variants` · `study stemma` · `study edition` · `study tei` · `study witnesses` · `study chain` |
| **思想史与接受史** | 一段经文被后世如何使用（直接引用、近似转录、节略、撮要、转述、解释性改写、引而驳之、套语相似），逐条给出规则与数值；一部书的历代接受与传播渠道 | `study reuse` · `study transmission` |
| **文献断代与作者** | 篇章文风分层（置换检验）、变点与离群篇章；逐篇的引书、晚出词汇与避讳证据；Burrows' Delta 作者归属 | `study layers` · `study dating` · `study authorship` |
| **临床文献研究** | 医案逐诊结构化（四诊、辨证、治法、方药剂量、加减、服药数、转归）；诊疗序列模式、诊次转移、与转归的关联（非疗效证据） | `study cases` · `study trajectories` |
| **医理与词义** | 论证图（条件、推断、因果、转折、取象比类、驳斥、界说、主治）与两书论证方式比较；义项分期、变点与候选新义 | `study argument` · `study senses` |
| **辑佚** | 从引书中辑出佚书条文，按出处注的卷次排序、合并重出；先在存世书上验证方法，给出各引书的可信度 | `study fragments` |
| **一问到底（V2）** | 问题编译为技能工作流（S01 来源 → … → S15 审计），四个核心智能体按各自权限执行，每步产物落入可续跑的工作区，答案的每条陈述都经审计 | `ask` · `skills` |
| **古今转译** | 古代表型包（否定、或然、假设、治后、预后、修饰、病程、人群、历史名称的义项）；HPO 投射与关系类型；现代疾病谱的定性强度、鉴别所需与古今名称关系；由今病溯古 | `bridge phenotype` · `bridge map` · `bridge reverse` · `bridge verify` |
| **证据审计与图谱** | 论断拆解为原子论断，逐条按类核查（原文逐字、训释出处、以今律古、证据层级、推论跳跃、临床建议）；六层证据图谱与溯源路径 | `audit` · `graph` |
| **现代证据与真实世界** | PubMed 记录按设计与对象分级、跨层防护、安全提示；真实世界问题 → 研究规格 → 只读参数化 OMOP 查询 | `modern search` · `modern safety` · `rwd ask` · `rwd synth` |
| **版面、实体、今译、地域** | 竖排阅读顺序与双行小注、多模态识读、OCR 对库核对；24 类语境实体；五层今译；医家籍贯、序跋落款与地域统计 | `vision` · `study entities` · `study translate` · `study places` |
| **知识发现** | 多智能体研究：失传知识、概念演变、方剂演化、隐性关联、矛盾发现、佚书线索；逐字证据、证伪、门控、专家核验 | `research` · `report` · `workspace` · `review` |
| **所有人（网页）** | 类 ChatGPT / Claude 的多轮对话：默认服务免填密钥（MiniMax-M3），也可自选模型，调用全部工具作答，引文逐字核对、出处一点即读（横排 / 竖排）；研究面板与工具台；对话存于本机浏览器，可导出 | [网页](https://chat.impf.ai/) · `serve` · `web build` |
| **开发者** | 插件化内核、能力注册、工具网格（73 个工具）、智能体配置（YAML）、事件溯源与重放、评测与架构治理；各任务输出的 JSON Schema | `agents` · `eval` · `governance` · `schema --study` |

## 二、快速开始

**网页**：直接打开 <https://chat.impf.ai/>（浏览器内运行，要籍语料；默认服务免填密钥）；或接入全部古籍（全量语料，构建见下文）：

```bash
pip install -e .
taochronos serve                   # http://localhost:8765 ：网页对话 + 全量语料（已构建时）+ 模型转发；网页“设置 → 运行环境 → 连接”
taochronos serve --env-keys        # 模型密钥从本机环境变量读取（MINIMAX_API_KEY …），网页里不必填写
taochronos serve --host 0.0.0.0    # 供其他机器使用：启动时打印访问令牌与带令牌的地址（--token 或 TAOCHRONOS_TOKEN 可指定）
taochronos web build -o _site      # 构建静态站点（GitHub Pages 由 .github/workflows/pages.yml 自动部署）
```

**命令行**：

```bash
pip install -e ".[dev]"            # Python ≥ 3.11；数据与配置位于仓库根目录（或设置 TAOCHRONOS_HOME）
taochronos demo                    # 离线运行“消渴”示例研究（确定性过程，约 4 秒，演示语料）
taochronos study formula 六味地黄丸 # 治学：方源考（没有全量语料时在演示语料上运行）
taochronos agents                  # 16 个智能体及其当前路由
```

接入全量语料（原文不进入 git；各来源的抓取、编目、入库都可复现，见[第三节](#三语料)）：

```bash
taochronos corpus fetch kanripo && taochronos corpus ingest kanripo     # 四库全书·医家类 100 部
taochronos corpus unpack jicheng jc_1_4_8_all.7z.001 jc_1_4_8_all.7z.002 jc_1_4_8_all.7z.003
taochronos corpus catalog jicheng && taochronos corpus ingest jicheng    # 笈成整理本（使用者提供）
taochronos corpus fetch cmeta && taochronos corpus catalog cmeta && taochronos corpus ingest cmeta   # CMETA 精校本（逐页对影像）
taochronos corpus images all --enrich                                    # 影像见证：各馆数字化古籍的书目与 IIIF 清单（只取元数据）
taochronos corpus status                                                 # 书数、段数、字数、分期与分层统计
```

治学（有全量语料时自动使用 `full-corpus` 画像；默认输出 Markdown，`--json` 输出完整结果，`-o` 写文件）：

```bash
taochronos study concordance "太陽之為病，脈浮，頭項強痛而惡寒"    # 经文互见·集注
taochronos study formula 小柴胡汤                                   # 方源考
taochronos study herb 柴胡                                          # 药性源流
taochronos study term 温病                                          # 术语源流
taochronos study taboo                                              # 避讳断代（全库概览；或给出书的 id）
taochronos study citations 张仲景                                   # 引用接受史（不给对象则输出引书网络）
taochronos study cards --book 伤寒论 --formula 桂枝汤 --herb 柴胡 --anki cards.tsv
taochronos study reading 温病                                       # 阅读门径
taochronos study dataset --formula 桂枝汤 --herb 柴胡 --term 温病 --citations -o datasets/guizhi
taochronos study metrology 三两 --year 200                          # 约41.4–46.8克（秦汉制）——历史计量，不是用药建议
```

深层发现 2.0：

```bash
taochronos study stemma 伤寒论                                      # 版本谱系：异文单元、谱系树、分组与污染
taochronos study tei 伤寒论 -o shanghan.tei.xml                     # TEI P5 校勘记
taochronos study witnesses 伤寒论                                   # 版本与影像见证：库中录本 + 各馆数字化刻本、抄本
taochronos study reuse "太陽之為病，脈浮，頭項強痛而惡寒"            # 语义复用：后世如何引用、节略、转述、驳斥这段经文
```

## 四、治学：结合古籍特性的深度挖掘

治学层（`plugins/classics/study`，[docs/study.md](docs/study.md)，[ADR 0004](docs/adr/0004-study-layer.md)）是一组确定性的函数，
回答文献研究与学习中的具体问题。它们的结果都由**见证**构成——逐字引文 + 段落编号 + 《书》卷·篇·节 + 年代与时期 + 文本层次 +
录文来源与授权——每一句结论都能回查原文。

### 古籍的特性与相应的处理

| 古籍特性 | 治学层的处理 |
|---|---|
| 一书多本、后书转引、不注出处的沿袭 | 经文互见区分**同书异本 / 引文 / 互见**，并为高覆盖的见证出**校勘记**（异文、脱、衍、倒，逐条列出见证） |
| 避讳改字改名 | 薯蓣→薯药（唐代宗）→山药（宋英宗）、玄参→元参、丸→圆（宋钦宗）等全部写法都检索；避讳用字反过来给出**版本年代下限** |
| 同名异方、同方异名 | 方剂按药味组成分组：同名而组成不同的分开，组成相同而名称不同的按药味检出 |
| 笈成本把方名、药名印为条目标题 | 全库“条目标题”索引（缓存）找到正文中不出现名称的条目，并跨段读取主治、组成与服法 |
| 历代度量衡不同 | 剂量按见证本身年代的计量折算（秦汉一两约 13.8–15.6 克，宋以后约 37–41 克；“分”在 960 年前后含义不同）；配伍比例与计量无关 |
| 学说有时代性 | 归经、升降浮沉是金元学说，本经无载是应然而非缺失；给出每一性能的**首见**及其年代 |
| 断代不确定、注疏晚于正文 | “最早”按**可能的最晚年代**（terminus ante quem）排序，只知朝代的书不会排在有确年的书之前；早于被引者的引用（注本中随正文断代的后人按语）另计 |
| 各时代存世文献多寡悬殊 | 术语频率比较“含该词段落 / 该期全部段落”，给 95% Wilson 区间与 Cochran–Armitage 趋势检验，不比较绝对数 |
| 方剂靠歌诀传习 | 在歌诀类书中找五言、七言、点到方名并念出药味（含“姜”“芍”“茱”“薯”之类省称）的**方歌**，逐行分段的歌诀自动拼合 |

### 深层发现 2.0：文献自身的结构

上面九个功能回答关于一方、一药、一词的问题；下面七个能力读出文献自身的结构（[docs/study.md](docs/study.md#深层发现-20--the-structure-of-the-literature)，
[ADR 0005](docs/adr/0005-deep-discovery-capabilities.md)）。三条原则：

- **能力，而不是智能体**：每一项都是治学层的确定性函数，同时是工具网格中的工具（`study.variants` … `study.fragments`，权限
  `classics:read`）与命令行命令，由现有智能体调用——校勘者（Philologist）用校勘、地层、断代与作者归属，质疑者（Skeptic）用复用、
  断代与论证，证据官（Evidence）用医案、轨迹与论证，语义官（Semanticist）与治学者（Scholar）用语义演变；谱系边自带复用类型。
  没有新增智能体。
- **候选不等于证明**：字符探针、概念共现、聚类、向量相似度只负责召回候选；类型由透明规则依据可测量的特征判定，每个标签都附上
  触发的规则与读到的数值。编码器的相似度只报告，不被任何规则读取。
- **先测后信**：每一项都有评测套件——能构造答案的用合成数据，需要样例的规则用开发集，文献学已有定论的在真实语料上核查。

（来源、逐字、校勘、义项、抽取、独立来源、时间、专家、现代证据）→ 发现分数 `D = w1·E + w2·N + w3·R + w4·T + w5·F − w6·A`
（始终与分量一起报告）→ 置信向量（文本、训诂、语义、抽取、跨源、时间、统计、现代映射；现代生物医学有效性默认 **unknown**）。
历史术语与现代概念之间只能是带类型的映射（related / partially_overlapping / uncertain / not_equivalent），只有人类专家能认定“等价”。

**研究合同与审查边界**（[ADR 0009](docs/adr/0009-boundaries-contract-and-evaluation-layers.md)）：

- **引文 ≠ 解读**：主张提交前要过“语义支持”——引文逐字为真之外，还要**陈述**出这条关系：最近的提示词管辖各个药物
  （「不可发汗，宜桂枝汤」）、后果决定是警示还是推荐（「汗之则神昏」/「汗之则愈」）、以“之”指代的方药按代词读、每个论元连同其否定
  一起读（「非风、非寒…乃异气所感」不支持“风致温疫”）；陈述框架记录谁在说（或曰……余曰非也：作者作答之后即作者本人之言）、
  立场（主张 / 转述 / 驳斥）、条件（若…者、凡…、「…者，X主之」）、否定与时间。被引文反驳的主张在提交时即被拒。
- **提议 ≠ 裁决**：每个事件带有发出者的主体（内核 › 人类 › 验证者 › 智能体），由会话从身份对象写入；G7 只由专家设定；
  质疑意见是状态机（提出 → 提议解决 → 关闭）：模型只能提议，硬性意见只有验证者复核通过才关闭。
- **执行完毕 ≠ 研究被接受**：合同逐条判定每个假说（在其当前版本上），每条标准记下评判者、观察、要求与失败后果；
  每个假说附**论证书（warrant）**：推理、假设、该发现类型的竞争解释（排除 / 未决 / 不适用 / 未处理）与区分性分析；
  预测可在探索时被留出的“确认集”上检验；统计为选择感知的（多断点取最大值的置换检验、留一来源家族、家族自助法）；
  新颖性限定范围（“未在指定范围内发现”，从不称“首次发现”）；Elo 只是**探索优先级**，不是可信度。
- **内部分数 ≠ 外部证据**：留出材料对智能体的每条读取路径都不存在（视图 + 结果防火墙）；G8 按现代证据的立场与层级判定
  （相反的人体证据判失败）；模型代码只在命名空间隔离层运行，否则拒绝运行。
- **长程运行**：预算“先预留、后结算”写入事件日志，续跑从账本开始；长工具结果分页而不截断；模型回复可录制与精确重放
  （`--record-llm` / `--replay-llm`）；证据可撤回并传播（撤出所支持的假说、作废相关门控、重判合同）；任务可取消与重试。
- **缺席论证 ≠ 样本中的缺席**（[ADR 0010](docs/adr/0010-speed-cruxes-and-research-value.md)）：“后世失传”（D1）与“隐性关联”（D4）
  是对文献的断言，不是对会话所读样本的断言。怀疑者在整个研究范围（大语料为契约时间窗内的整个库）检索**明确陈述**该关联的主张
  （含单字写法，由抽取器判定、引文须支持）：转折年之后只要有一处经核验的陈述即驳倒“失传”（`restated_after`），任何一处陈述即驳倒
  “隐性”（`attested`）；二者都是硬性意见，改写措辞无法关闭。
- **经文公案**：从库中注本收集校勘疑义（倒装、当作、衍文、脱文、存疑），生成可审阅的登记表（伤寒论 85 条、金匮要略 42 条）；
  字面上支持、却落在注家疑义文字上的主张读作“存疑”（ambiguous），并列出疑义与注家。

### 设计原则

| 原则 | 在代码中的体现 |
|---|---|
| **Deterministic Harness, Stochastic Intelligence** | 内核（事件溯源、事务、门控、停止条件）完全确定；模型只在需要判断的角色中出现，其输出必须通过模式校验与逐字核验 |
| **Everything is a Plugin** | 语料、领域包、检索、治学、模型、沙箱、存储都是插件；模式挖掘、统计与治学是工具优先的确定性过程 |
| **Claims, not facts** | 主张是“某书某版某处这样说”的超边，而非脱离语境的医学事实 |
| **No forced single reading** | 有异文之处保留各读法的概率和“不确定”质量 |
| **No medical anachronism** | 古今概念只有带类型的映射；“等价”只能由专家认定 |
| **Propose, don't commit** | 智能体只能提议修改规范知识；校验器或人类决定 |
| **Evidence-first** | 没有逐字证据的结论不会写入；伪造或改写的引文被机械核验拦截 |
| **The harness decides when to stop** | 证据饱和、无新来源、门控通过、预算耗尽或需专家介入——由内核判断 |
| **Authority from identity** | 权限来自身份对象，不来自字符串；每个事件带主体，归约器按事件类型检查；智能体只拿到绑定自身身份的会话视图与只读状态 |
| **Execution ≠ acceptance** | 任务跑完不等于研究成立：合同在假说当前版本上逐条评判，报告只能呈现按当前版本评判过的假说 |

## 六、使用场景

**研究者**

- *一首方的源流*：`study formula 肾气丸` → 原方（《金匮要略》崔氏八味丸）、通行方、同方异名（桂附地黄丸/汤）、各本剂量比例、
  历代主治与加减；`--json` 或 `study dataset --formula 肾气丸` 得到逐条见证表，做进一步统计。
- *一味药的性能演变*：`study herb 附子` → 本经“温、有毒”，《证类本草》“大毒”，《汤液本草》“大热、阳中之阳”，
  归经之说在所收本草中首见于清初《本草择要纲目》（手少阳、足少阴、三焦、命门）——每一变化都给出首见之书、年代与原文。
- *一个概念的历史语义*：`study term 中风` → 分期频率与趋势、各期搭配（明代语境中“半身不遂”“拘急”突出）、历史义项；
  再以 `research … --focus 中风 --forbid 中风=脑卒中` 做可证伪的概念演变研究。
- *一部书的版本*：`study taboo <book_id>` → 讳例计数与版本年代下限；与 `study concordance` 的同书异本比对互为印证。
- *学术传承*：`study citations` 看各期宗主；`study citations 李杲` 看东垣学说的接受史。
- *一部书的版本谱系*：`study stemma 伤寒论` → 各本的异文单元、谱系树、共同异文分组与污染；`study tei` 导出 TEI 校勘记，
  `study edition <book_id>` 看某一本与其他各本的一致率、独有异文、缺文与增文。
- *一部书有哪些本子可读、可看*：`study witnesses 伤寒论` → 库中各录本的底本、年代、藏所、来源与授权（CMETA 本的段落可直接打开所据页面的
  影像），以及各馆数字化的刻本与抄本（年代、刻/写、藏所、索书号、IIIF 清单、授权），按年代排列。
- *一段经文的接受史*：`study reuse <经文>` → 后世逐条的复用类型与判定规则（谁照录、谁节略、谁改写解释、谁引而驳之）；
  `study transmission 伤寒论` 看一部书各时代被保留、改造、争议的比例与传播渠道。
- *一部经典的成书层次*：`study layers 素问` 与 `study dating 素问` 并读——文风说明篇章“不同”，引书、晚出词汇与避讳说明它们
  “可能何时写成”；`study authorship` 以 Burrows' Delta 比较候选作者。
- *医案研究*：`study cases --book <id>` 逐诊读出四诊、治法、方药加减与转归；`study trajectories 咳嗽` 看历代医家的诊疗序列
  （记录中的关联，不是疗效证据）。
- *辑佚*：`study fragments 小品方` 辑出佚文并注明每条的引书与卷次；`--verify` 先在存世书上检验方法与各引书的可信度。
- *可复现发表*：数据包带语料指纹（书数、段数、来源、规范化版本、目录摘要），同一语料上重算结果一致。

**学生与自学者**

- `study cards --book 伤寒论 --anki shl.tsv`：伤寒论全部“……者，某方主之”的方证填空卡，导入 Anki 间隔复习；
- `study cards --formula 桂枝汤 --formula 小柴胡汤`：组成、剂量、炮制、煎服法，附方歌；
- `study cards --herb 柴胡 --herb 附子`：本经与后世本草的性味归经对照；
- `study reading 温病`：从素问、伤寒到温病条辨的阅读门径，每部书写明为什么读；
- `study concordance`：读到一句经文，看它在历代被谁引用、怎样改写。
- `study argument "<一段经文>"`：看一段条文怎样推理——条件、推断、因果、转折、取象比类、驳斥、界说、主治逐条标出；
  `study senses 消渴`：看一个词在各时代的义项与变迁。

## 七、模型与部署

默认完全离线：所有智能体都有确定性过程（procedure），治学层不需要模型。判断型角色可以走模型：

```bash
pip install -e ".[anthropic]"
export ANTHROPIC_API_KEY=...
taochronos demo --profile claude   # Opus 5（前沿层）/ Sonnet 5（中层）/ Haiku 4.5（小层）
```

Claude 提供者默认开启服务端拒答回退（`fallbacks="default"`，适用于 Opus 5）；若模型拒答、输出无法通过模式校验或预算耗尽，
该任务回退到确定性过程，并把回退记录为一条 Decision。

**国内与多平台接入**（详见 [docs/models.md](docs/models.md)）：MiniMax 国内站（`minimax`，`api.minimax.cn`，`MINIMAX_API_KEY`）与国际站、
Poe（`poe`，`POE_API_KEY`，以机器人名为模型名）、LiteLLM（`litellm` 包，`<provider>/<model>`；或 `litellm-proxy`）、DeepSeek、通义
（DashScope）、Kimi（Moonshot）、智谱 GLM、豆包（火山方舟）、硅基流动、OpenRouter、本地 vLLM/Ollama。治学、桥接、审计、识读与工作流
命令都接受 `--llm 平台:模型`（及 `--llm-max-calls`、`--llm-max-cost`、`--llm-refresh`）；画像 `minimax`、`poe`、`litellm` 把推理模型与
复核模型一并配好。模型调用逐次缓存、计入预算、按 JSON 模式校验（一次修复机会）、记日志（不记提示词）；结果标明每项由规则、模型
还是二者共同决定。外部命令子智能体与 Research Code Mode 见 [docs/agents.md](docs/agents.md)。

**网页对话 · 道乃久**（[docs/web.md](docs/web.md)、[ADR 0011](docs/adr/0011-web-client.md)、默认服务与对话记录见 [ADR 0012](docs/adr/0012-default-service-relay.md)）：智能体道乃久（TaoChronos，模型 Tao-R1），由医哲未来
人工智能研究院（IMPF-AI）发布——TaoChronos 的工具与证据纪律加上你选择的底层模型（界面与指令中都标明底层模型；列表之外的服务可在“自定义 API”
中手动设置）。对话在浏览器里进行，经道乃久默认服务（免密钥）或用你自己的密钥直接调用，或经 `taochronos serve` 转发；TaoChronos 在浏览器内
（Pyodide，要籍语料：350 部要籍中 348 部的原文）或 `taochronos serve`（全量语料，全部古籍；浏览器记住连接过的服务）执行工具。模型以
“智能体”身份只获读与分析权限，默认直接看到 16 个常用工具、经目录按需调用其余工具；MiniMax-M3 的 `reasoning_details` 与工具调用逐轮原样回传，
Claude 经官方 SDK 调用（自适应思考、服务端拒答回退）。本机服务默认只绑定 127.0.0.1，只接受本机页面、服务自己的网页、已发布的网页与指定来源，
只向列出的模型平台转发；绑定到其他地址时必须凭访问令牌访问。全部古籍（约 2.2 GB，各来源授权不一）不随网站发布，经服务接入。

业务代码只向**能力注册表**请求能力（`corpus`、`domain`、`philology`、`lineage`、`retriever`、`study`、`llm`……），从不直接导入提供者；
插件由画像（`profiles/*.yaml`）装配。工具不导入插件，智能体只通过能力与工具行动，智能体、工具与插件不能铸造特权身份——这些都由 `taochronos governance` 强制检查。
每个事件带有发出者主体，由归约器按 `kernel/authority.py` 检查；事务整批预校验、提交后才持久化，失败则从日志恢复；每轮核对实时状态与日志重放一致
（增量进行：保留一份重放随新事件推进，实时状态每次重新计算哈希）。YAML 按内容哈希只解析一次；全量语料 harness 构建 9.2 秒 → 0.64 秒，
全量研究运行 152 秒 → 95 秒（其中完整性核对 44.5 秒 → 7.0 秒）。
详见 [docs/architecture.md](docs/architecture.md)、[ADR 0009](docs/adr/0009-boundaries-contract-and-evaluation-layers.md) 与 [ADR 0010](docs/adr/0010-speed-cruxes-and-research-value.md)。

## 十二、局限

- 语料未经本项目逐字校勘：四库本有清人删改与避讳改字，检索与抽取所用的白文分句为规则式（`study punctuate` 另以学得的模型句读，只插入标点）；笈成本为志愿者录入，品质不一；断代在无人工考定时
  依据书籍信息与序跋落款，无从考定者只能保守定为“清代或更早”。
- 治学层与抽取器是规则式的机器阅读：方剂组成、本草条目与性能靠模式与词表读取，词表缺漏会使组成不全；只有一条见证的
  “孤例”与不常见的版式需要人工核对。所有输出都附原文，便于核查。
- 注本中未分层的后人按语随正文断代：早于被引者的引用会被识别并另计，但与正文同期或更早的引文（如孙星衍辑本《本经》按语引《说文》）
  仍计入正文时期。
- 度量衡数值、讳例起始年与医家生卒是有出处的学术观点，可能有争议，均为可审阅的 YAML；避讳证据只说明版本年代下限，属提示性证据。
- 去重按文本重合度判定，同一版本的两个录本与不同版本之间的界线并不绝对；被判为副本的书逐部记录，可以人工改判。
- 演示语料很小（23 部书、131 段节录），评测数值只具说明意义；Time Machine 与链接预测需要大规模语料才有统计意义。
- 深层发现 2.0 同样是规则式的：谱系树是对库中几个录本关系的假设，污染标记要人去核查；复用规则的阈值定在 33 对开发集上，
  词表之外的概念只能凭文字找到；文风会随题材变化（运气诸篇讲的就是运气），文风与断代证据单独都不能证明后增；医案解析按几种
  医案体例编写，其他体例可能切错病案；只有明确标记才成为论证边；候选新义只是语境词聚类，要人读例句后才算义项；辑文的可信度
  以各引书在存世书上的验证精确率为准。
- 任务规格的新能力同样有边界：句读衡量的是与某一编者的一致程度（断法本有分歧）；条文一片只取一个角色，《伤寒论》四成
  片段无规则认领；注文只在四种排版中找得到，立场只在点名引述处读出，不点名的异议不计；方证联系是共现而非疗效；学派是后世
  史家的归类，“用得更多”的词须读例句才算学说，成员少的学派统计力弱；名称只统计词表所载之名；传播链是由共同异文推出的
  假设，抄手各自独立的相同改动可能造成假边，故每条边附共享异文与边际。
- 影像见证按题名关联到库中著作：注释书与同名异书单凭题名无法区分，关联要人去核对；只收书目元数据，不下载影像，
  年代以各馆著录为准（只有年号的按该年号的起讫计）。
- V2 的边界：古今桥接的强度是规则给出的定性等级，**未经校准、不是概率**，只说表型相似、不作回溯诊断；64 种疾病谱与同名异义说明为
  研究筛查而编，需临床与医史专家审定；古代表型的写法表在留出集上召回 0.73，是桥接的主要局限（模型补读即为此设）；审计只核查
  机器能核查的部分（原文、训释、强度、证据类型、推论跳跃），不评判史家的论证；PubMed 的研究类型据索引而定，须抽样核对全文；
  真实世界数据只是带防护的编译器，在合成数据上的结果只检验编译，不是发现。
- 审查边界的局限：工具层面的留出（确认集）不等于真正的盲测预测；命名空间隔离不是虚拟机级隔离；合同的判定与强度等级是有序标签，
  **未经校准、不是概率**；语义支持是规则式的第二读者，经文公案只能读出注家明言的（登记表由规则收集，大黄牡丹汤、里水两例收集不到，
  即疑难解读留出集上的两个不安全错误，如实报告而未针对性修补）；疑难解读的金标准由作者标注。
- 研究价值层的局限：它衡量“预见”而非“影响”（后世写下即算成真，不论是谁先发现）；两侧都由规则抽取器阅读；全文索引的排序统计来自整库
  （不读取另一侧的任何段落）；端到端只有 39 条可判预测、区间很宽；“失传”尚无基线；确认家族在框架之外的其他段落尚未从整库检索中排除。
- 系统不提供医学建议；任何研究结论在专家（Gate G7）核验前都只是研究线索。
